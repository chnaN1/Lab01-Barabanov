## Контрольные вопросы

1. Почему программа может узнать имя компьютера, хотя вы не писали его в коде?
Она берет эти данные напрямую из самой Windows (из переменных окружения), где имя компьютера уже сохранено. Класс `Environment` просто умеет их оттуда читать.
2. Какую роль играет операционная система, когда программа запрашивает у неё данные?
Она работает как посредник. Программа не может сама залезть в железки компьютера, поэтому она «просит» операционную систему выдать ей нужные системные данные.
3. Что означает «64-битная ОС»? 
Это значит, что система работает на 64-битной архитектуре. Она может использовать много оперативной памяти (больше 4 ГБ) и быстрее обрабатывает данные за один такт.
4. Что показывает Environment.ProcessorCount и обязательно ли это число совпадает с числом физических ядер?
Оно показывает логические процессоры (потоки), а не физические ядра. Из-за виртуальных потоков (технологии SMT/Hyper-Threading) это число обычно в два раза больше реальных ядер. Например, у меня 6 ядер, а потоков — 12.
5. Чем память процесса (WorkingSet) отличается от всей оперативной памяти компьютера?
Память процесса — это маленький кусочек оперативки, который Windows выделила конкретно под нашу запущенную программу прямо сейчас. А общая RAM — это вся память компьютера для всех программ сразу.
6. Почему одна и та же программа без изменений в коде может показать разные результаты на разных компьютерах?
Потому что в коде нет готовых ответов, там написаны только команды опроса системы. На каком компьютере программу запустишь — данные той Windows она и выведет.
